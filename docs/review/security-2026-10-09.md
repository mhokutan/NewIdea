# Security review 2026-10-09

Team: API and website (senior model), mobile app (senior model), secrets, dependencies and headers sweep (Haiku).
Result: no Critical or High issues in our code. Fixed the same day unless marked "open".

## Fixed
- Report abuse: two "minor" reports no longer limit a profile automatically; they go to the top of the moderator queue.
- OTP codes stored hashed (Better Auth `storeOTP: "hashed"`); Better Auth reads the client IP from `cf-connecting-ip`.
- Chunked write requests refused (the 16 KB body check could be skipped without Content-Length).
- Gift claim: needs a profile, claim row first then stock, so double taps never use two units.
- Public view counts on creator pages count signed in viewers only (guest device ids can be scripted).
- `/health` returns a fixed error text; API sends HSTS and X-Frame-Options.
- Perk code key throws if `BETTER_AUTH_SECRET` is missing (no "dev-secret" fallback).
- Website: per IP rate limit (20/min) on `/admin` and the visit counter; waitlist no longer lets anyone overwrite another email's role or link.
- Developer early access form moved to `/developers.js` (the CSP blocked the inline script, the form did not work).
- App: every link from the API opens through `openExternal` (https only); API paths encode ids and handles.
- CI: GitHub Actions pinned to commit SHAs, eas-cli pinned (24.12.1), App Store key removed with `if: always()`.
- Root `.gitignore` covers .env, .dev.vars, *.p8, *.jks, *.keystore, service account and Google config files.
